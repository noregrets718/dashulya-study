# SPEC — dashulya-study

Учебный аналог бота [Dashulya](https://github.com/Lancetnik/dashulya) (MIT).
Цель проекта — **изучение фреймворка AG2 и основных компонентов** через
пошаговую сборку работающего Telegram-агента: сначала локально, затем на сервере.

## Цель и аудитория

- **Цель обучения:** пройти путь от пустого проекта до работающего агента,
  добавляя по одному компоненту за занятие и понимая каждый.
- **Цель продукта:** Telegram-бот с характером, инструментами и памятью,
  который отвечает в личке и в групповых чатах на обращения и вопросы,
  а также умеет находить и пересказывать прошлые обсуждения.
- **Аудитория:** автор проекта (владелец бота) и участники его групповых чатов.
  Проект одновременно служит портфолио.

## Объём и границы

Строим **собственную реализацию по мотивам Dashulya**, не форк. Повторяем
поведение и архитектурные идеи, но с нашими техническими решениями:

- Python **3.12** + `uv` (у оригинала 3.14 — нам не нужна самая свежая версия).
- Модель — **Ollama Cloud** через OpenAI-совместимый API (`https://ollama.com/v1`),
  вместо OpenAI.
- Заимствованные идеи/фрагменты сопровождаем ссылкой на источник и сохраняем
  MIT-уведомление.

Границы MVP (что должно работать к концу):

1. Агент отвечает в личке и ведёт диалог с историей.
2. Агент вызывает минимум один собственный инструмент.
3. Агент отвечает в групповом чате на обращение (имя/упоминание/ответ ей).
4. Агент сохраняет сообщения и находит по ним релевантные прошлые обсуждения.
5. Приложение разворачивается на сервере (Docker) с постоянным хранением.

**Не входит в MVP** (отдельные этапы/упражнения, по желанию): изображения и
стикеры, YouTube-сводки, веб-поиск, whisper-команды, система ролей/банов,
полный набор evals и мутационное тестирование.

## Роли

- **Владелец (owner)** — автор проекта. Единственный, кто общается в личке
  и управляет ботом командами.
- **Участник группы** — человек в групповом чате, где есть бот. Может обратиться
  к боту именем/упоминанием/ответом.
- **Бот** — агент: классифицирует, обращаются ли к нему, генерирует ответ,
  сохраняет и ищет сообщения.

## Ключевые сценарии

### S1. Диалог в личке
Владелец пишет боту, бот отвечает в характере; контекст текущего разговора
сохраняется; `/clear` сбрасывает историю.

### S2. Обращение в группе
Участник упоминает бота или отвечает на его сообщение; бот отвечает в тот же
чат, коротко и по делу.

### S3. Продолжение разговора
Бот недавно отвечал в группе; новое сообщение без имени бот оценивает сам:
промолчать, поставить реакцию или ответить текстом.

### S4. Память и поиск
Бот сохраняет полученные сообщения чата; по вопросу участника находит
релевантные прошлые сообщения, пересказывает и даёт ссылки на оригиналы.

## Критерии приёмки (по этапам)

| Этап | Критерий готовности |
|---|---|
| 0. Пустой проект | `uv run` отрабатывает, `.env` не коммитится, репозиторий публичный с README и LICENSE |
| 1. Первый агент | Один запрос к модели через AG2 и ответ в терминале |
| 2. Диалог | Несколько реплик с сохранением контекста; `/clear` сбрасывает |
| 3. Инструмент | Агент вызывает нашу Python-функцию и использует результат |
| 4. Наблюдение | Видны вызовы инструментов, ошибки и ход выполнения |
| 5. Telegram в личке | Владелец общается с ботом через Telegram |
| 6. Структурированный результат | Классификатор решает, обращаются ли к боту |
| 7. Групповой чат | Бот отвечает на обращение; контексты разных чатов изолированы |
| 8. Память | Сообщения сохраняются; поиск находит релевантное |
| 9. Продолжение разговора | Бот выбирает: ответить / реакция / промолчать |
| 10. Расширения AG2 | MCP / подтверждение человеком / изображения — отдельные занятия |
| 11. Сервер | Docker, постоянное хранение, логи, обновление |

## Требования

### Данные
- Секреты (ключи, токен Telegram) — только в `.env`, вне Git.
- Реальные сообщения чатов не попадают в публичный репозиторий.
- История/память (с шага 8) хранится в PostgreSQL.

### Интеграции
- Модель: Ollama Cloud, OpenAI-совместимый API.
- Telegram: Bot API через `aiogram`.
- PostgreSQL (с шага 8).

### Эксплуатация
- Локальная разработка: macOS, `uv`, Python 3.12.
- Развёртывание (шаг 11): Docker, Docker Compose, логи, обновления.

## Словарь

- **Агент (agent)** — сущность AG2, которая ведёт диалог с моделью и вызывает инструменты.
- **Инструмент (tool)** — функция Python, которую модель может вызвать в ходе ответа.
- **Обращение (addressing)** — решение, адресовано ли сообщение боту.
- **Продолжение (continuation)** — решение бота после своего ответа: текст / реакция / тишина.
- **Память (memory)** — сохранённые сообщения и поиск по ним.
- **Контекст (context)** — сообщения, подаваемые модели в текущем запросе.

## Принципы

1. **Один компонент за занятие.** Понимание важнее скорости; крупное — делим.
2. **Код пишет ученик.** Наставник объясняет, даёт задание и критерии, проверяет.
3. **Работающий результат после каждого шага.** Каждый этап заканчивается запускаемым кодом.
4. **Сначала просто, затем усложняем.** Инфраструктура (DI, ParadeDB, evals) добавляется
   только когда её требует конкретная задача, а не «на вырост».
5. **Секреты и реальные данные вне Git.** Публичный репозиторий — портфолио, а не утечка.

## Зафиксированные технические решения

- Язык/зависимости: Python 3.12, `uv`, пакет AG2 (`ag2[openai]`).
- AG2 API текущей версии: `from ag2 import Agent, tool`,
  `OpenAICompletionsConfig(model, api_key, base_url)`.
- Модель: Ollama Cloud, `base_url=https://ollama.com/v1`, ключ `OLLAMA_API_KEY`.
- Telegram: `aiogram` 3.x.

## Открытые вопросы (решаем по ходу)

1. **Конкретная модель Ollama Cloud** — выбираем после проверки вызова инструментов
   (шаг 3) и структурированного вывода (шаг 6).
2. **Поддержка structured output / decisions** выбранной моделью — если не поддержит,
   обсуждаем замену модели или локальный Ollama.
3. **Глубина повторения памяти** — на шаге 8 решаем, воспроизводим ли ParadeDB/pgvector
   полностью или начинаем с простого SQL-поиска и усложняем отдельным занятием.
